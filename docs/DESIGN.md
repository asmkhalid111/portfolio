# Design Direction — v0.1 Draft

## Design thesis
An engineer's personal field notes / technical editorial portfolio: calm, articulate, precise, warm, built on substantive project evidence. Human-made, distinct; not a copied startup landing page.

## Constraints
- Hero immediately explains who the owner is, what they build, and where to see work.
- Show selected projects above the fold or early on the page; clear CTAs to case studies/GitHub.
- Typography, rhythm, whitespace, meaningful project images and strong hierarchy carry the visual identity.
- One restrained color accent; choose palettes/fonts intentionally and record tokens.
- Dark mode is optional, not a blocker; default design must be coherent.
- Avoid synthetic stats, meaningless gradient blobs, generic feature cards, stock-photo portraits, neon glows, endless animated text, fake testimonials, giant wall-of-badges.
- Mobile-first, keyboard accessible, reduced motion, semantic headings and contrast.
- Motion must convey navigation or state, not slow down reading.
- Admin area may use conventional ergonomic UI without forcing editorial public styling.

## Workflow
At M05, produce 2–3 distinct low-fidelity directions and select one before coding. Adopt suitable Hallmark principles (tokens, page-specific design, visual audits) without outsourcing judgement to a theme randomizer. Record chosen composition and rejected alternatives.
